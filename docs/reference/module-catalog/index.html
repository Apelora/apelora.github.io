    Module catalog reference

    Generated by npm run catalog:doc from packages/module-catalog/src. Do not edit by hand.

    83 modules in 12 categories. * = required, (1) = single cable. Every module also has a net input (NIC) as its last left-hand terminal.

    Metrics says where the software's own metrics come from (built in, a separate exporter, an optional agent in the guest, Incus, or none), then the port and path, the format when it is not metrics text, and whether they are off or reachable only on localhost by default. "(set)" marks a port the class chooses because the software has no default. A class whose metrics a collector reads as text on a port has a mon output, and a drawn mon connection opens exactly that port (MODULE-PORTS.md). How to turn each one on, the signals worth watching and how well the facts were checked are in packages/module-catalog/src/metrics.ts and in the Studio inspector.

    Deployable modules

    3 of 83 classes have an Incus runtime; the others are design-only. A runtime is added only after its images have run on the disposable test cluster. The runtime decides the instance kind: a system container unless the class needs an OCI application container or a virtual machine (how a module becomes instances).
