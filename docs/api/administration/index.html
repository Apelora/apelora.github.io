    Administration API

    API tokens for scripts and automation: list, create and revoke them. This page lists 3 operations.

    Set variables in the API overview. Download OpenAPI.

    Operations

    OperationWhat it does
    GET /api/v1/tokensAPI tokens, active and revoked (never the tokens themselves).
    POST /api/v1/tokensCreates an API token, shown only in this response.
    DELETE /api/v1/tokens/{id}Revokes an API token; it stops working at once.

    Details

    GET /api/v1/tokens

    API tokens, active and revoked (never the tokens themselves). Needs manage-tokens.

    Operation ID: tokens

    Needs: manage-tokens.

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.

    curl --fail-with-body -sS -X GET "$APELORA_URL/api/v1/tokens" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Accept: application/json"

    TypeScript:

    const result = await client.request("tokens", {});

    Response 200 — Success.

    Content-Type: application/json.

    Example response from a test installation; your IDs, names and times differ.

    {
  "items": [
    {
      "id": "7c8d9b09-0c9d-43fa-9c1e-9af63f22dc4e",
      "name": "docs-verifier",
      "role": "fabric-admin",
      "createdAt": "2026-10-25T17:19:58.587603Z",
      "expiresAt": "2026-10-26T17:19:58.559696Z",
      "revokedAt": null,
      "lastUsedAt": "2026-10-25T17:20:01.441074Z"
    }
  ]
}

    Errors. The body is {"error": {"code": …, "message": …}}; see error codes for the codes every operation shares.

    StatusCodes
    401unauthenticated, invalid_token
    403forbidden, mfa_required
    503database_not_configured

    POST /api/v1/tokens

    Creates an API token, shown only in this response. Needs manage-tokens and every permission the token's role carries (a token never does more than its creator). A fabric-admin token also needs another person's approval of token.create_admin on token:fabric-admin, sent as Apelora-Approval; an API token cannot present one, so it cannot create fabric-admin tokens.

    Operation ID: create_token

    Needs: manage-tokens and every permission the token's role carries (a token never does more than its creator).

    ParameterInTypeRequiredDefaultMeaning
    Apelora-Approvalheaderstring (uuid)no—For a fabric-admin token: the approval another person granted for token.create_admin on token:fabric-admin

    Request body (JSON):

    FieldTypeRequiredMeaning
    expiresInDaysinteger or nullno1–365 days; 90 when omitted.
    namestringyesWho or what uses it, e.g. "ci" or a person's name.
    roleone of fabric-admin, operator, studio-designer, auditoryesWho may do what. Every API route names the permission it needs; roles map to permissions here and nowhere else.
    {
  "name": "monitoring",
  "role": "operator",
  "expiresInDays": 90
}

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.

    This request can change state. Check permissions, prerequisites and any required approval before running it.

    curl --fail-with-body -sS -X POST "$APELORA_URL/api/v1/tokens" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  --data-raw '{"name":"monitoring","role":"operator","expiresInDays":90}'

    With options (Apelora-Approval):

    # APPROVAL_ID: the id of the approval another person granted (POST /api/v1/approvals).
curl --fail-with-body -sS -X POST "$APELORA_URL/api/v1/tokens" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Accept: application/json" \
  -H "Apelora-Approval: $APPROVAL_ID" \
  -H "Content-Type: application/json" \
  --data-raw '{"name":"backup-site-admin","role":"fabric-admin","expiresInDays":30}'

    TypeScript:

    const result = await client.request("create_token", { body: { name: "monitoring", role: "operator", expiresInDays: 90 } });

    Response 201 — Success.

    Content-Type: application/json.

    Example response from a test installation; your IDs, names and times differ.

    {
  "token": "<token, shown once>",
  "info": {
    "id": "4372a6ec-2e44-4ada-8ec4-f120dc2f833e",
    "name": "monitoring",
    "role": "operator",
    "createdAt": "2026-10-25T17:20:01.446621Z",
    "expiresAt": "2027-01-23T17:20:01.446142Z",
    "revokedAt": null,
    "lastUsedAt": null
  }
}

    Errors. The body is {"error": {"code": …, "message": …}}; see error codes for the codes every operation shares.

    StatusCodes
    400invalid_request
    401unauthenticated, invalid_token
    403approval_unavailable, token_exceeds_caller, forbidden, mfa_required
    409approval_invalid, approval_required
    503database_not_configured

    DELETE /api/v1/tokens/{id}

    Revokes an API token; it stops working at once. Needs manage-tokens.

    Operation ID: revoke_token

    Needs: manage-tokens.

    ParameterInTypeRequiredDefaultMeaning
    idpathstring (uuid)yes—Token id

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.

    This request can change state. Check permissions, prerequisites and any required approval before running it.

    curl --fail-with-body -sS -X DELETE "$APELORA_URL/api/v1/tokens/4372a6ec-2e44-4ada-8ec4-f120dc2f833e" \
  -H "Authorization: Bearer $APELORA_TOKEN"

    TypeScript:

    await client.request("revoke_token", { params: { id: "4372a6ec-2e44-4ada-8ec4-f120dc2f833e" } });

    Response 204 — Success, with no body.

    Errors. The body is {"error": {"code": …, "message": …}}; see error codes for the codes every operation shares.

    StatusCodes
    401unauthenticated, invalid_token
    403forbidden, mfa_required
    404—
