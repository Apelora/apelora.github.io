    Alerts API

    Built-in alerts, acknowledgement and silences, and the webhook channels that receive them. This page documents all 12 operations, each with a request you can copy. Set APELORA_URL and APELORA_TOKEN as described in the API overview.

    Operations

    OperationWhat it does
    undefinedFiring alerts (most severe and oldest first) with acknowledgement and silence, the silences in force, counts by severity and whether the evaluator runs.
    undefinedAcknowledges a firing alert: who, when and an optional note.
    undefinedWebhook channels with their delivery state.
    undefinedAdds a webhook channel.
    undefinedChanges a webhook channel.
    undefinedDeletes a webhook channel; messages still waiting for it are dropped by the relay.
    undefinedQueues a test notification for one channel through the same outbox path as real alerts; the channel's delivery state shows the outcome within seconds.
    undefinedResolved alerts, newest first, paged by before.
    undefinedThe built-in rules with their parameters in force, their defaults and what the evaluator's last pass said about each source.
    undefinedChanges a rule's parameters (on or off, threshold within the rule's bounds, duration up to a day, severity).
    undefinedSilences a rule (every subject, or one) for minutes from now: no notification is sent for its alerts that fire or resolve meanwhile.
    undefinedEnds a silence now.

    Details

    GET /api/v1/alerts

    Firing alerts (most severe and oldest first) with acknowledgement and silence, the silences in force, counts by severity and whether the evaluator runs.

    Needs: cluster.view.

    curl -sS -X GET "$APELORA_URL/api/v1/alerts" \
  -H "Authorization: Bearer $APELORA_TOKEN"

    Response 200:

    {
  "actions": {
    "configure": {
      "allowed": false,
      "reason": "example"
    },
    "respond": {
      "allowed": false,
      "reason": "example"
    }
  },
  "alerts": [
    {
      "comparison": "at-least",
      "id": 1,
      "lastSeenAt": "2026-01-01T09:00:00Z",
      "rule": "example",
      "runbook": "example",
      "severity": "info",
      "startedAt": "2026-01-01T09:00:00Z",
      "state": "example",
      "subject": "example",
      "summary": "example",
      "threshold": 1,
      "title": "example",
      "unit": "example",
      "value": 1
    }
  ],
  "counts": {
    "critical": 0,
    "info": 0,
    "needsAttention": 0,
    "warning": 0
  },
  "evaluator": {
    "message": "example",
    "stale": false,
    "durationSecs": 1,
    "everySecs": 1,
    "lastPassAt": "2026-01-01T09:00:00Z",
    "worker": "example"
  },
  "silences": [
    {
      "createdBy": "example",
      "endsAt": "2026-01-01T09:00:00Z",
      "id": "00000000-0000-4000-8000-000000000001",
      "note": "example",

    Errors: 401, 403, 503. The body is { "error": { "code": …, "message": … } }.

    POST /api/v1/alerts/{id}/acknowledge

    Acknowledges a firing alert: who, when and an optional note. It keeps firing until its condition clears; acknowledging tells others someone is on it. Refused (409) when it is not firing (not_firing) or was acknowledged already (already_acknowledged).

    Needs: alert.respond; audited as alert.acknowledge.

    ParameterInTypeRequiredMeaning
    idpathintegeryesAlert id

    Request body (JSON):

    FieldTypeRequiredMeaning
    notestringnoWhat is being done about it (at most 500 characters).
    {
  "note": "example"
}
    curl -sS -X POST "$APELORA_URL/api/v1/alerts/00000000-0000-4000-8000-000000000001/acknowledge" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"note":"example"}'

    Response 200:

    {
  "comparison": "at-least",
  "id": 1,
  "lastSeenAt": "2026-01-01T09:00:00Z",
  "rule": "example",
  "runbook": "example",
  "severity": "info",
  "startedAt": "2026-01-01T09:00:00Z",
  "state": "example",
  "subject": "example",
  "summary": "example",
  "threshold": 1,
  "title": "example",
  "unit": "example",
  "value": 1
}

    Errors: 400, 401, 403, 404, 409, 503. The body is { "error": { "code": …, "message": … } }.

    secretRefstringyesThe name of the environment variable on the worker holding the signing secret, e.g. APELORA_ALERT_SECRET_OPS. Never the secret itself.
    urlstringyeshttps://… only, without a user name or password.

    DELETE /api/v1/alerts/channels/{id}

    Deletes a webhook channel; messages still waiting for it are dropped by the relay.

    Needs: alert.configure; audited as alert.channel.delete.

    ParameterInTypeRequiredMeaning
    idpathstringyesChannel id
    curl -sS -X DELETE "$APELORA_URL/api/v1/alerts/channels/00000000-0000-4000-8000-000000000001" \
  -H "Authorization: Bearer $APELORA_TOKEN"

    Response 204, with no body.

    Errors: 401, 403, 404, 503. The body is { "error": { "code": …, "message": … } }.

    POST /api/v1/alerts/silences

    Silences a rule (every subject, or one) for minutes from now: no notification is sent for its alerts that fire or resolve meanwhile. Evaluation and history go on.

    Needs: alert.respond; audited as alert.silence.create.

    Request body (JSON):

    FieldTypeRequiredMeaning
    minutesintegeryes1 to 10080 (a week).
    notestringno—
    rulestringyes—
    subjectstringnoOne subject; absent: every subject of the rule.
    {
  "rule": "example",
  "minutes": 0
}
    curl -sS -X POST "$APELORA_URL/api/v1/alerts/silences" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"rule":"example","minutes":0}'

    Response 201:

    {
  "createdBy": "example",
  "endsAt": "2026-01-01T09:00:00Z",
  "id": "00000000-0000-4000-8000-000000000001",
  "note": "example",
  "rule": "example",
  "ruleTitle": "example",
  "startsAt": "2026-01-01T09:00:00Z",
  "createdByName": "example",
  "subject": "example"
}

    Errors: 400, 401, 403, 503. The body is { "error": { "code": …, "message": … } }.
