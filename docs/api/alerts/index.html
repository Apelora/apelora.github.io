    Alerts API

    Built-in alerts, acknowledgement and silences, and the webhook channels that receive them. This page lists 12 operations.

    Set variables in the API overview. Download OpenAPI.

    Operations

    OperationWhat it does
    GET /api/v1/alertsFiring alerts (most severe and oldest first) with acknowledgement and silence, the silences in force, counts by severity and whether the evaluator runs.
    POST /api/v1/alerts/{id}/acknowledgeAcknowledges a firing alert: who, when and an optional note.
    GET /api/v1/alerts/channelsWebhook channels with their delivery state.
    POST /api/v1/alerts/channelsAdds a webhook channel.
    PUT /api/v1/alerts/channels/{id}Changes a webhook channel.
    DELETE /api/v1/alerts/channels/{id}Deletes a webhook channel; messages still waiting for it are dropped by the relay.
    POST /api/v1/alerts/channels/{id}/testQueues a test notification for one channel through the same outbox path as real alerts; the channel's delivery state shows the outcome within seconds.
    GET /api/v1/alerts/historyResolved alerts, newest first, paged with after and next.
    GET /api/v1/alerts/rulesThe built-in rules with their parameters in force, their defaults and what the evaluator's last pass said about each source.
    PUT /api/v1/alerts/rules/{rule}Changes a rule's parameters (on or off, threshold within the rule's bounds, duration up to a day, severity).
    POST /api/v1/alerts/silencesSilences a rule (every subject, or one) for minutes from now: no notification is sent for its alerts that fire or resolve meanwhile.
    DELETE /api/v1/alerts/silences/{id}Ends a silence now.

    POST /api/v1/alerts/{id}/acknowledge

    Acknowledges a firing alert: who, when and an optional note. It keeps firing until its condition clears; acknowledging tells others someone is on it. Refused (409) when it is not firing (not_firing) or was acknowledged already (already_acknowledged). Needs alert.respond; audited as alert.acknowledge.

    Operation ID: acknowledge_alert

    Needs: alert.respond; audited as alert.acknowledge.

    ParameterInTypeRequiredDefaultMeaning
    idpathintegeryes—Alert id

    Request body (JSON):

    FieldTypeRequiredMeaning
    notestring or nullnoWhat is being done about it (at most 500 characters).
    {
  "note": "Looking into the failed job"
}

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.
