    Documentation/API

    Inventory API

    What exists in the cluster, as Incus reports it: servers and capacity, instances and their logs, Incus projects, networks, storage pools and volumes nobody owns, and preflight checks. This page lists 14 operations.

    Set variables in the API overview. Download OpenAPI.

    Operations

    OperationWhat it does
    GET /api/v1/capacityHow much CPU, memory and volume space the cluster has free, per server and in total, for comparing with a design.
    GET /api/v1/clusterThe Incus server and its cluster members.
    GET /api/v1/instancesInstances in all projects.
    GET /api/v1/instances/{project}/{name}The instance with the application it belongs to, its recent jobs, and what the caller may do (Start, Stop, Restart, Move and Delete go through the existing instance routes and jobs).
    GET /api/v1/instances/{project}/{name}/console-logThe end of the instance's console log (tailKib, default 64, at most 1024).
    GET /api/v1/instances/{project}/{name}/logsThe instance's log files as Incus lists them (names only).
    GET /api/v1/instances/{project}/{name}/logs/{file}The end of one of the instance's log files (tailKib, default 64, at most 1024).
    GET /api/v1/networksNetworks in all projects.
    GET /api/v1/networks/settingsThe network settings in effect: Apelora's uplink and service range, each deploy project's network limits, and the uplink as Incus reports it (with the administrator identity, when configured), with what does not fit together.
    GET /api/v1/preflightRead-only readiness checks of the Incus server or cluster, of the projects Apelora deploys into, and of the image mirrors (whether each image server the catalog uses is mirrored and whether the mirrors answer).
    GET /api/v1/projectsIncus projects.
    GET /api/v1/storage-poolsStorage pools.
    GET /api/v1/storage/orphansCustom volumes in Apelora's projects that no application volume or backup record refers to, in every pool, with their size.
    GET /api/v1/storage/poolsStorage pools with how full each is, per member and in total (read from each member's state, like the Health page).

    GET /api/v1/capacity

    How much CPU, memory and volume space the cluster has free, per server and in total, for comparing with a design. Read-only. With cluster.view servers are named; with capacity.view (held by designers and operators at any scope) they are numbered.
