    Applications API

    Applications: drafts and published versions, planning and deploying a version, start, shut down, stop, restart and migrate, status and events, networks, and volumes with their snapshots, backups and schedules. This page lists 34 operations.

    Set variables in the API overview. Download OpenAPI.

    Operations

    OperationWhat it does
    GET /api/v1/applicationsApplications the caller may see, each with design status, derived runtime status, replica health, and the actions they may take now.
    POST /api/v1/applicationsCreates an application in an environment, optionally with its first draft.
    GET /api/v1/applications/{name}One application with its modules (desired and observed), versions and recent operations.
    PATCH /api/v1/applications/{name}Changes an application's description or icon (its name cannot change).
    POST /api/v1/applications/{name}/archiveArchives an application that is not running; it leaves the default list and keeps its data.
    POST /api/v1/applications/{name}/deploymentsDeploys the design: saves it as a new revision and queues the planned changes.
    GET /api/v1/applications/{name}/draftThe application's working document.
    PUT /api/v1/applications/{name}/draftSaves the draft as the next version.
    GET /api/v1/applications/{name}/eventsWhat happened to the application: creation, saves, versions, deployments, operations, refusals.
    GET /api/v1/applications/{name}/migrationDry run of migrating the application to another server: for each instance whether it keeps running, what is copied and what blocks it.
    GET /api/v1/applications/{name}/operationsRecent operations of the application, newest first.
    POST /api/v1/applications/{name}/operationsStarts, shuts down (graceful), stops (immediate), restarts or migrates the application's instances, in dependency order where that matters, as an asynchronous operation.
    GET /api/v1/applications/{name}/operations/{id}One operation with the progress of each phase and instance.
    POST /api/v1/applications/{name}/planWhat deploying the design would change, without changing anything.
    POST /api/v1/applications/{name}/restoreBrings an archived application back.
    GET /api/v1/applications/{name}/statusThe application's instances as Incus reports them, by module.
    GET /api/v1/applications/{name}/versionsVersions of the application, newest first.
    POST /api/v1/applications/{name}/versionsReleases the current draft as the next immutable published version.
    GET /api/v1/applications/{name}/versions/{revision}The document of one version.
    GET /api/v1/applications/{name}/volumesThe application's volumes, with what Incus says about each now.
    PATCH /api/v1/applications/{name}/volumes/{volume}Grows one of the application's volumes, also while its instance runs.
    DELETE /api/v1/applications/{name}/volumes/{volume}Deletes one of the application's volumes and its snapshots, for good.
    GET /api/v1/applications/{name}/volumes/{volume}/backupsThe volume's backups, oldest first, whether each still exists, and its schedules.
    POST /api/v1/applications/{name}/volumes/{volume}/backupsBacks the volume up now: a copy, through a short-lived snapshot, into the backup pool on another member.
    DELETE /api/v1/applications/{name}/volumes/{volume}/backups/{backup}Deletes one backup copy.
    GET /api/v1/applications/{name}/volumes/{volume}/backups/{backup}/restoreDry run of restoring the volume from one of its backups: what is replaced (data written since the backup, the volume's snapshots), which instances must be stopped, where the safety backup goes, and the steps.
    POST /api/v1/applications/{name}/volumes/{volume}/backups/{backup}/restoreRestores the volume from one of its backups, after the dry run passes again and the volume's name is typed: a safety backup of the current data first (unless declined), then the backup is copied over the volume.
    PUT /api/v1/applications/{name}/volumes/{volume}/schedulesSets or turns off the volume's snapshot and backup schedules.
    GET /api/v1/applications/{name}/volumes/{volume}/snapshotsThe volume's snapshots, oldest first.
    POST /api/v1/applications/{name}/volumes/{volume}/snapshotsTakes a snapshot of the volume, named after the time (snap-YYYYMMDD-HHMMSS).
    DELETE /api/v1/applications/{name}/volumes/{volume}/snapshots/{snapshot}Deletes one snapshot of the volume.
    POST /api/v1/applications/{name}/volumes/{volume}/snapshots/{snapshot}/restorePuts the volume back to a snapshot: everything written since is lost.
    GET /api/v1/networks/applicationsEach application the caller may view that has a recorded deployment: its network, the rules compiled from its design, its service and published addresses, and what Incus holds for each, with the differences.
    GET /api/v1/storage/volumesEvery application volume the caller may see, with what Incus reports, its schedules and how many backups it has.
