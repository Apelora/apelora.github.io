    Audit API

    The append-only audit log: search and export. This page lists 2 operations.

    Set variables in the API overview. Download OpenAPI.

    Operations

    OperationWhat it does
    GET /api/v1/auditAudit events the caller may read, newest first, filtered by actor, target, action prefix, outcome and time, and paged with before.
    GET /api/v1/audit/exportExports the audit events the caller may read, with the same filters as the list (limit does not apply), newest first, as CSV or JSON lines.

    Details

    GET /api/v1/audit

    Audit events the caller may read, newest first, filtered by actor, target, action prefix, outcome and time, and paged with before. Needs audit.read (platform-wide, or limited to the events of the caller's organisations, projects and applications) and a database.

    Operation ID: audit

    Needs: audit.read (platform-wide, or limited to the events of the caller's organisations, projects and applications) and a database.

    ParameterInTypeRequiredMeaning
    actorquerystringnoWho acted: their stable id (user:<uuid>, service:<uuid>, token:<name>) or, ignoring case, the name they had when they acted.
    targetquerystringnoWhat was acted on, exactly as recorded (e.g. local-account:ada or a group's name).
    actionquerystringnoOnly actions starting with this, e.g. role. or emergency_access..
    outcomequerystringnosuccess, denied or failed.
    fromquerystringnoRFC 3339: events at or after this time.
    toquerystringnoRFC 3339: events before this time.
    beforequeryintegernoOnly events older than this id (paging: the id of the last event of the previous page).
    limitqueryintegernoEvents per page, 1 to 500 (default 100). Not used by the export.

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.

    curl --fail-with-body -sS -X GET "$APELORA_URL/api/v1/audit" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Accept: application/json"

    Response 200 — Success.

    Content-Type: application/json.

    GET /api/v1/audit/export

    Exports the audit events the caller may read, with the same filters as the list (limit does not apply), newest first, as CSV or JSON lines. Streamed one database page at a time. Needs audit.read; the export itself is audited as audit.exported with its filters.

    Operation ID: audit_export

    Needs: audit.read; the export itself is audited as audit.exported with its filters.

    ParameterInTypeRequiredMeaning
    actorquerystringnoWho acted: their stable id (user:<uuid>, service:<uuid>, token:<name>) or, ignoring case, the name they had when they acted.
    targetquerystringnoWhat was acted on, exactly as recorded (e.g. local-account:ada or a group's name).
    actionquerystringnoOnly actions starting with this, e.g. role. or emergency_access..
    outcomequerystringnosuccess, denied or failed.
    fromquerystringnoRFC 3339: events at or after this time.
    toquerystringnoRFC 3339: events before this time.
    beforequeryintegernoOnly events older than this id (paging: the id of the last event of the previous page).
    limitqueryintegernoEvents per page, 1 to 500 (default 100). Not used by the export.
    formatquerystringnocsv or jsonl (one JSON object per line, as the list returns them). Default jsonl.

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.

    For text/csv:

    curl --fail-with-body -sS -X GET "$APELORA_URL/api/v1/audit/export?format=csv" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Accept: text/csv"

    For application/x-ndjson:

    curl --fail-with-body -sS -X GET "$APELORA_URL/api/v1/audit/export?format=jsonl" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Accept: application/x-ndjson"

    Response 200 — The events: CSV with a header row, or one JSON object per line.

    Content-Type: text/csv.
