    Documentation/API

    Deployment API

    Creating, changing, moving and deleting single instances, and the jobs that carry out those changes and deployments: list, follow, cancel and retry. This page lists 10 operations.

    Set variables in the API overview. Download OpenAPI.

    Operations

    OperationWhat it does
    POST /api/v1/instancesQueues creation of an instance.
    DELETE /api/v1/instances/{project}/{name}Queues deletion of an Apelora instance (stopped first if running).
    GET /api/v1/instances/{project}/{name}/moveDry run of moving an instance to another member: whether it keeps running, what it copies, what blocks it.
    POST /api/v1/instances/{project}/{name}/moveMoves an Apelora instance to another member, after the check runs again and its name is typed: live when it can, otherwise only with allowStop, copying its volumes there.
    POST /api/v1/instances/{project}/{name}/stateQueues starting or stopping an Apelora instance.
    GET /api/v1/jobsJobs newest first, filtered by status, kind and application and paged with after.
    GET /api/v1/jobs/{id}A queued job and its progress.
    POST /api/v1/jobs/{id}/cancelCancels a job.
    GET /api/v1/jobs/{id}/detailA job with its attempts (worker, timings, outcome, error and the Incus operations each started), who queued it, its request id, and the jobs linked to it (retries, and other jobs the same request queued).
    POST /api/v1/jobs/{id}/retryQueues a new job that repeats a failed one, linked to it (retryOf); the failed job is kept unchanged as evidence.

    POST /api/v1/instances

    Queues creation of an instance. Needs deploy. Apelora marks it as its own; only such instances can later be stopped or deleted through Apelora.

    Operation ID: create_instance

    Needs: deploy.

    ParameterInTypeRequiredDefaultMeaning
    Idempotency-Keyheaderstringno—Makes the request safe to repeat

    Request body (JSON):

    FieldTypeRequiredMeaning
    architectureslist of stringnoArchitectures the image is known to run on, as Incus names them (x86_64, aarch64, …); empty allows any. Checked against the cluster before creating and against the instance Incus created.
    configobjectnoExtra instance config; keys under user.apelora. are reserved.
    config.<key>stringnoAny key.
    kindone of container, virtual-machine, unknownyescontainer (system or OCI) or virtual-machine.
    namestringyes—
    networkobject or nullno—
    network.aclstringyes—
    network.networkstringyes—
    network.uplinkstringyesUplink network the application network is created on.
    ownerobject or nullno—
    owner.applicationstringyes—
    owner.modulestringyes—
    owner.replicaintegerno—
    profileslist of stringnoProfiles to apply, in order; empty applies the project's default profile.
    projectstringyes—
    rootPoolstring or nullnoThe pool of the root disk when it is not the one the project's profile gives: the shared pool for a module that restarts on another member after a failure. Set by the control plane from the module's volume classes, never by a caller.
    sourceobjectyesWhere an instance's root image comes from.
    source.aliasstringyesAlias such as debian/13 or, for OCI, repository:tag. Pin an OCI image by digest: repository@sha256:<64 hex digits>.
    source.fingerprintstring or nullnoPins a simplestreams image: the full SHA-256 fingerprint Incus gives it. The instance must then be built from exactly this image.
    source.protocolone of simplestreams, ociyesHow Incus fetches an image.
    source.serverstringyesImage server URL, e.g. a simplestreams server or an OCI registry.
    startbooleannoStart the instance once created.
    volumeslist of objectnoPersistent volumes, each created for this instance on the member it runs on.
    volumes[].classone of data-local, data-replicatednoThe policy a volume is created under.
    volumes[].contentone of filesystem, blocknoWhat the volume holds: a mounted filesystem or a raw disk (virtual machines only).
    volumes[].namestringyesName in the design, e.g. data: lowercase letters, digits and -, at most 16.
    volumes[].pathstring or nullnoWhere a filesystem volume is mounted inside the instance; none for a block volume.

    GET /api/v1/jobs

    Jobs newest first, filtered by status, kind and application and paged with after. Whole platform readers (read-inventory) see every job; anyone else the jobs of applications they may view.

    Operation ID: jobs

    Needs: a signed-in caller; the server decides what that caller may see.

    ParameterInTypeRequiredDefaultMeaning
    statusquerystringno—pending, running, succeeded, failed or cancelled.
    kindquerystringno—Only kinds starting with this, e.g. instance. or volume.restore.
    applicationquerystringno—Only the jobs of this application.
    afterquerystringno—Paging: the next of the previous page.
    limitqueryintegerno100Jobs per page, 1 to 200 (default 100).

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.

    curl --fail-with-body -sS -X GET "$APELORA_URL/api/v1/jobs" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Accept: application/json"

    With options (status, application, limit):

    curl --fail-with-body -sS -X GET "$APELORA_URL/api/v1/jobs?status=pending&application=shop&limit=1" \
  -H "Authorization: Bearer $APELORA_TOKEN" \
  -H "Accept: application/json"

    Next page: repeat the request with after set to the response's next. The last page has no next.

    TypeScript:

    const result = await client.request("jobs", { query: { status: "pending", application: "shop", limit: 1 } });

    POST /api/v1/jobs/{id}/cancel

    Cancels a job. A waiting job with nothing in flight is cancelled at once (cancelled); otherwise the request is recorded (requested) and the worker stops at the job kind's next safe point, never in the middle of an Incus change (see safePoints on the job's detail). Repeating the request changes nothing. Refused (409 job_finished) for a finished job. Needs the permission that queues that kind of job on its target; audited.

    POST /api/v1/jobs/{id}/retry

    Queues a new job that repeats a failed one, linked to it (retryOf); the failed job is kept unchanged as evidence. Needs the permission that queues that kind of job on its target. Refused (409) when the job did not fail (not_failed), was retried already (already_retried), a newer job for the same target was queued since (superseded), or it is an application operation (not_retryable: start it again from the application). Audited.

    Operation ID: retry_job

    Needs: a signed-in caller; the server decides what that caller may see.

    ParameterInTypeRequiredDefaultMeaning
    idpathstring (uuid)yes—Job id
    Idempotency-Keyheaderstringno—Makes the request safe to repeat

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.

    This request can change state. Check permissions, prerequisites and any required approval before running it.

IDEMPOTENCY_KEY=$(uuidgen)
