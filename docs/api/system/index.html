    System API

    Health, versions, sign-in, settings, support bundles and caller identity. This page lists 16 operations.

    Set variables in the API overview. Download OpenAPI. Examples: MOCK VERIFIED (tested with simulated inventory); Illustrative (schema values).

    Operations

    OperationWhat it does
    GET /api/v1/database-backupsWhether Apelora's database is being backed up and a restore has been proven, from the records the scripts leave in APELORA_DB_BACKUP_DIR.
    GET /api/v1/healthReports that the service answers, the inventory provider, the authentication mode and whether Incus is reachable.
    GET /api/v1/health/componentsThe state of each part of this installation: control plane, database, deployment workers, job queue, Incus, networks, storage pools and identity providers.
    GET /api/v1/health/serversEach server's status, CPU, memory, storage and the instances on it, with warnings.
    GET /api/v1/image-mirrorsImage mirrors: the configuration this control plane runs with (upstream → mirror pairs and whether only mirrors may be used; URLs, not secrets), whether each mirror answers (probed at most once a minute), and the image servers each deployable catalog class needs with whether it is covered.
    PUT /api/v1/me/passwordChanges the caller's own password (local accounts only).
    GET /api/v1/monitoringWhere each metrics endpoint is, whether the caller may scrape, and the region, site and sector labels.
    GET /api/v1/settingsThe settings this control plane runs with: every setting the control plane and the worker read, the value when it may be shown (never a secret, a key or a certificate path), whether it is the default and where it came from; sign-in settings saved in the Console; the workers seen recently.
    GET /api/v1/sign-inHow people can sign in to this control plane.
    POST /api/v1/sign-in/passwordSigns a person in with a username and password and returns an Apelora session.
    POST /api/v1/sign-in/setupSets a local account's password with its one-time setup link (24 hours, single use).
    POST /api/v1/sign-outEnds the Apelora session the request was made with.
    GET /api/v1/support-bundleDownloads a support bundle (a tar file, streamed): manifest, versions, effective settings (secrets never included), health, preflight, jobs that failed in the last 24 hours with their attempts, a metrics snapshot and where to find logs.
    GET /api/v1/systemVersions of this control plane and the Incus release it is pinned to, and when the certificates Apelora uses to reach Incus expire, and Incus as observed now (running version, or the error that keeps it unreachable).
    GET /api/v1/whoamiWho is calling, with the role assignments and permissions in force.
    GET /metricsMetrics of this control plane in the text exposition format (OpenMetrics when the Accept header asks for application/openmetrics-text).

    Changes the caller's own password (local accounts only). Every other session of theirs is revoked; the one making the request stays. Counts towards the account's lock like a sign-in.

    Operation ID: change_password

    Needs: a signed-in caller; the server decides what that caller may see.

    Request body (JSON, illustrative values):

    FieldTypeRequiredMeaning
    currentstringyes—
    newstringyes—
    {
  "current": "example",
  "new": "example"
}

    Example request. Replace sample names, IDs and body values with resources and settings from your installation.
