About monitoring

When a server fails, you know what happens next.

Health is written in words, with the reason and the next step. Fabric restarts a module on another server only once it knows the first one has stopped.

  • Stopped first. A failed server is "fenced": proven stopped, so two servers never write the same disk.
  • Measured. A container with data ran again 144 to 155 seconds after its server was force-stopped, in three lab drills.
  • Virtual machines are not drilled yet. That is on the roadmap.

More about recovery

From drawing to running application.

Fabric owns the application: its design, connections, replicas and health. Incus, the open-source system that runs containers and virtual machines on a cluster, owns the servers. Fabric talks to Incus only through its documented API.

  1. Design

    Connect modules on a canvas in Studio.

  2. Plan

    See what would be created, resized or removed, and whether it fits.

  3. Deploy

    A worker creates the instances as durable jobs. A crash or a repeated request never makes duplicates.

  4. Operate

    Health, recovery, backups and the audit log run from the Console.
