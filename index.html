Built for teams that run their own servers.

If that is you, Fabric replaces a pile of hand-kept files. If it is not, it is better to know now.

A good fit if you

  • run Linux servers of your own, or plan to, and want one place to see and control them
  • keep container, network and firewall files in step by hand today
  • need roles, approvals and an audit trail, or work without internet access

Not yet a fit if you

  • need a proven production platform today: Fabric is in early development and has run only on a lab
  • want a hosted service: you run Fabric on servers you own
  • need many ready-to-run application types: three modules deploy today (NGINX, Debian and a Linux virtual machine)

See the whole cluster in one place.

Fabric Console shows servers, health and every change. Maintenance, joining servers and cluster settings happen here, with a preview before anything changes.

  • Servers and the cluster database majority, at a glance.
  • Every change is a job you can follow, retry, or cancel at a safe point.

More about operating

When a server fails, you know what happens next.

Health is written in words, with the reason and the next step. Fabric restarts a module on another server only once it knows the first one has stopped.

  • Stopped first. A failed server is "fenced": proven stopped, so two servers never write the same disk.
  • Measured. A container with data ran again 144 to 155 seconds after its server was force-stopped, in three lab drills.
  • Virtual machines are not drilled yet. That is on the roadmap.
Real Incus testedVirtual machines: roadmap

More about recovery

From drawing to running application.

Fabric owns the application: its design, connections, replicas and health. Incus, the open-source system that runs containers and virtual machines on a cluster, owns the servers. Fabric talks to Incus only through its documented API.

  1. Design

    Connect modules on a canvas in Studio.

  2. Plan

    See what would be created, resized or removed, and whether it fits.

  3. Deploy

    A worker creates the instances as durable jobs. A crash or a repeated request never makes duplicates.

  4. Operate

    Health, recovery, backups and the audit log run from the Console.

What is available, and what is not yet.

Fabric is in early development. This is the line between the two.

Available now

Run on a disposable four-server lab.

  • Designer, deploy, network rules and service addresses
  • Containers and virtual machines created in Incus
  • Replicas, health checks and restart of failed replicas
  • Volumes, snapshots, backups and restore
  • Recovery of a container's data after a server fails
  • Roles, approvals, audit and the Fabric Console

On the roadmap

Designed or planned, not built, or not yet tested.

  • Restarting virtual machines after a server dies
  • Installing operating systems on new servers through MAAS
  • Rebalancing running instances, and staged upgrades with rollback
  • IPMI power control, and Redfish on a real management controller
  • More deployable modules than the three today
  • Production use on real servers
